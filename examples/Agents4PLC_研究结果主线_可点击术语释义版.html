01

建立 PLC 代码生成基准与专业知识库

构建可评估、可检索的领域数据基础，为后续代码生成与验证提供统一依据。

方法分叉
RAG 专业案例库构建
  • 从 OSCAT 自动化库收集 510 个真实 ST 案例。
  • 通过 MATIEC 编译筛选，并结合 LLM 辅助预处理与人工选择。
  • 筛选得到 201 个包含计划且语法正确的 ST 程序，作为 RAG 语料。
  • 案例按 SHA-256 功能索引、带 I/O 映射的控制流计划、ST 代码片段组织；代码经 RuSTy 语法验证。
  • 整合 456 页领域资料与经典 ST 代码数据，支持检索。
标准基准任务集
  • 构建 168 个标准化 PLC 编程任务，并配套 604 个人工验证属性。
  • 任务来源：PLC 教科书、整理后的开源示例、ST 编程竞赛，以及基于真实需求优化的 GPT-4 案例。
  • 每项任务包含自然语言 instruction、经验证的 ST ground truth，以及人工编写的 CTL 验证属性。
  • 由 25 名 PLC 工程师进行难度评分；最终划分为 30 个简单任务、81 个中等任务和 4 个困难任务，中等与困难合并为 85 个高级任务。
高保真任务集
  • 另构建 21 个高复杂度任务，来源于工业编程竞赛。
  • 为任务补充形式化属性，形成可验证的高保真评测集。
  • 该数据集用于 RQ2 效率与可靠性分析，并尽量降低公开大模型训练数据污染风险。

02

形成五智能体协同的闭环代码生成框架

将自然语言需求拆解为可执行计划，再完成代码生成、验证与迭代修复。

方法分叉
AgentR｜检索代理
  • 建立本地 PLC 领域知识库，存储书籍、标准文档、历史计划与 ST 案例。
  • 第一阶段：使用 text-embedding-ada-002 进行向量匹配，召回 Top-3 候选案例。
  • 第二阶段：LLM 从控制逻辑、任务类别和底层算法三个维度评分并重排序。
  • 将候选案例整理为问题描述、规划蓝图和代码文档，结构化传递给 AgentP；可选调用网络搜索补充案例。
AgentP｜规划代理
  • 分析自然语言需求，提炼总体功能目标并拆分为 POU。
  • 为各 POU 明确输入/输出变量、功能边界及变量映射。
  • 将实现逻辑组织为步骤式流程或状态机逻辑。
  • 生成多个候选计划，并按目标达成度、效率和安全性进行 LLM 评分排序；按优先级依次交给 AgentC。
AgentC｜编码代理
  • 利用 AgentR 检索到的案例，为代码生成提供领域知识、可复用逻辑和语法参考。
  • 采用 CoT 分解生成步骤：确定 POU 顺序、变量声明作用域，再逐步映射执行逻辑。
  • 使用 one-shot 模板约束 IEC 61131-3 代码结构，明确 PROGRAM / FUNCTION_BLOCK 等 POU 组织及输入输出分离。
  • 加入语法感知约束：变量先声明后使用、禁止嵌套 POU 定义、硬件地址映射仅保留在注释中。
AgentV｜验证代理
  • 编译检查：先调用 ST 编译器检查语法；失败时将诊断信息传给 AgentD。
  • 属性生成：从用户需求提取原子命题，选择时序逻辑模式，将命题映射到提升的 CTL 模板并组合成形式属性。
  • 形式验证：借助 PLCverif 等工具将 ST 转换为验证格式，再调用 SMV / CBMC 等后端进行属性检查。
  • 通过确定性的输入/输出处理与扫描周期模拟验证代码功能；输出验证通过结果或反例。
AgentD｜调试代理
  • 编译错误修复：定位并分类语法、类型不兼容、未定义符号、常量溢出等错误。
  • 根因分析：结合编译器诊断与代码上下文，推断错误来源。
  • 模板化补丁：将错误映射到符合 IEC 61131-3 的修复模板，生成结构化统一差异补丁。
  • 语义错误修复：结合 CoT 分析被违反的属性与模型检查反例，定位逻辑缺陷并生成补丁。
  • 将修复代码重新交给 AgentV 验证；若仍失败则继续迭代，超过循环限制后尝试下一候选计划。

03

多模型对比实验显示代码正确性提升

在简单任务与高级任务上，Agents4PLC 相较直接使用基础模型获得更高的最终验证通过率。

方法分叉
评测任务与模型设置
  • 使用 30 个简单任务和 85 个高级任务开展主要对比实验。
  • 基础模型包括 GPT-4o、GPT-4o-mini、DeepSeek-V3、Claude 3.5 Sonnet、Qwen2.5-Max 和 GLM-4-Plus。
  • 不同方法尽可能使用相同模型后端；通用多智能体及 RAG 基线主要采用 GPT-4o 评估。
对比基线
  • 纯 LLM 直接生成：作为基础模型基线。
  • LLM4PLC：微调模型结合外部验证工具的 PLC 代码生成管线。
  • RAG 增强生成：将检索到的 PLC 案例作为上下文。
  • 通用多智能体框架 ChatDev：比较多角色协作生成代码的效果。
  • 同时参考 Koziolek 等人的 GPT-4o + RAG 配置。
评价指标
  • SSR｜语法成功率：生成代码中能够无错误编译的比例。
  • VR｜可验证率：已编译代码中，能够转换为形式化验证语言并至少验证 80% 属性的比例。
  • PR｜通过率：全部生成代码中，能够编译且通过至少 80% 形式化属性验证的比例。

04

前置规划提高首轮正确性，并减少修复轮次

检索与规划将更多计算前置，降低对反复调试的依赖；但单轮开销和总耗时并未同步下降。

方法分叉
实验数据与迭代设置
  • 效率分析覆盖标准数据集中的 115 个案例，并重点使用 21 个高保真复杂任务。
  • 设置最多 5 轮迭代优化，记录每轮生成、验证和修复表现。
  • 通过不同轮次的 SSR、PR 变化，分析首次生成能力与后续迭代收益。
首轮正确性与迭代轨迹
  • 比较 Agents4PLC、LLM4PLC 与直接 GPT-4o 的首轮生成表现。
  • 重点考察高级任务首轮准确率，判断检索增强规划和前置验证能否减少后续修复。
  • 观察第 1—5 轮 SSR、PR 的变化，区分局部补丁修复与重新规划带来的改进。
计算成本与效率
  • 统计平均优化轮数、每轮平均 Token、总 Token 消耗。
  • 统计每轮平均耗时与总耗时，比较前置检索/规划带来的单轮开销。
  • 对比直接 GPT-4o、LLM4PLC 和 Agents4PLC 的成本—可靠性权衡。

05

消融实验揭示关键模块贡献与性能权衡

语法约束、RAG 示例与结构化补丁共同影响代码质量；检索上下文也可能在部分高级任务中引入噪声。

方法分叉
检索与规划模块消融
  • 移除检索：关闭 AgentR 的检索增强，观察案例上下文对生成质量的影响。
  • 移除检索与规划：同时移除检索和规划支撑，评估 AgentR、AgentP 的联合贡献。
编码代理 AgentC 消融
  • One-shot + 语法提示：保留模板和语法约束，移除 RAG 示例。
  • One-shot + RAG：保留模板和检索示例，移除语法提示。
  • One-shot：仅保留一次性模板。
  • Zero-shot：不提供示例模板，观察无示例生成效果。
调试代理 AgentD 消融
  • 直接修复：让模型直接改写代码，不使用结构化统一差异补丁。
  • 基本模板：移除 CoT 指令和专门修复模板，仅提供基础语法指导。
验证—调试循环消融
  • 移除循环：只执行单轮代码生成与验证，不进行验证反馈后的迭代修复。
  • 所有消融配置保持相同任务集、评价指标与验证标准，以比较模块贡献。
统一评价方式
  • 在 30 个简单任务和 85 个高级任务上分别统计 SSR、VR 与 PR。
  • 比较语法可编译性、形式属性可验证性和最终通过率，识别各模块对不同复杂度任务的作用。
