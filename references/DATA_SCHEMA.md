# 结构化数据与构建器接口

> 使用 `python scripts/build_html.py paper.json output.html`。构建器读取论文专属 JSON，将图像嵌入独立 HTML。本文档是 Skill 的正式数据结构规范，审稿人视角四问已整合在本文件中。

## 顶层字段

| 字段 | 类型 | 用途 |
|---|---|---|
| `page_title` | string | 浏览器选项卡标题 |
| `heading` | string[] | 首元素中文标题；第二元素原论文题目（可只有一个） |
| `citation` | string | 论文作者、年份、期刊简明信息 |
| `reviewer_view` | object | 审稿人视角四问；新论文建议必填 |
| `navigation` | string[] | 与 `nodes` 等长的短导航词，可省略 |
| `nodes` | object[] | 真实研究结果/综述认识模块，推荐 3—7 项 |
| `terms` | object | 术语名 → `[英文全称, 中文名称, 释义, 本文作用]` |
| `figures` | object | 图号字符串 → `{image, source, panels}` |

## `reviewer_view`：审稿人视角四问

新论文建议提供该对象。构建器会将其显示在论文标题和引用信息之后、研究结果主线之前。旧版 JSON 可以不含该字段，构建器仍能兼容。

```json
{
  "reviewer_view": {
    "research_question": "[论文原文] 研究要解决的核心问题、重要性和解决后的价值。",
    "prior_work": "[前人文献] 前人主要研究路线和已有进展。[审稿人评价] 仍需关注的不足。",
    "core_intuition": "[合理推断] 用直观语言概括论文的本质想法，并说明推理依据。",
    "worked_example": {
      "scenario": "[论文原文] 论文中的真实代表性案例及上下文。",
      "input": "实际输入的数据、样本、变量、空间/时间范围和关键参数。",
      "processing": "按原文顺序描述预处理、模型/实验步骤、对照和验证。",
      "output": "论文实际报告的输出、指标或观察结果。",
      "interpretation": "[合理推断] 该输出回答了什么问题，以及不能据此推出什么。"
    }
  }
}
```

### 四个字段的写作要求

| 字段 | 必须回答的问题 | 写作约束 |
|---|---|---|
| `research_question` | 要解决什么？为什么重要？解决后有什么价值？ | 区分作者声称的价值和审稿人判断的价值，不泛泛拔高 |
| `prior_work` | 以前怎么做？还差在哪里？ | 按研究路线归纳；区分作者明确指出的空白与分析者判断 |
| `core_intuition` | 论文的本质想法是什么？ | 建议 2—4 句话，按“问题→关键关系/机制→解决思路→验证”说明 |
| `worked_example` | 真实案例如何从输入走到输出？ | 必须可追溯；按场景、输入、处理、输出、解释边界组织 |

`worked_example` 的五个子字段均为字符串：
- `scenario`：案例场景。优先使用论文真实样本、流域、站点、实验组、影像或时间段。
- `input`：输入数据、样本对象、变量、范围和参数。
- `processing`：真实处理流程，不能将并列方法强行拼成顺序流程。
- `output`：论文实际报告的指标、结果或观测现象。
- `interpretation`：结果支撑什么结论、不能推出什么。

如果论文没有单个可追踪案例，可以基于原文真实设置构造简化示例，但必须在 `scenario` 中写明“基于原文设置的简化示例”。不得编造输入数值、处理参数、输出指标或实验现象。原文未提供的信息应明确写“原文未报告”。

### 证据归属标签

建议在四问和其他分析字段的关键陈述中使用以下标签：

- `[论文原文]`：目标论文直接陈述的事实、方法、数据或实验观察；尽可能附章节、页码、图表编号。
- `[前人文献]`：其他研究已经报告的结论或方法；注明作者/年份或参考文献编号。
- `[合理推断]`：根据现有证据作出的解释，写出推理依据，使用审慎措辞。
- `[不确定/待验证]`：原文证据不足，明确指出缺少什么。
- `[审稿人评价]`：独立评价研究重要性、创新性、方法适配性、验证充分性和结论边界。

不得把目标论文转述的前人结论冒充目标论文的新发现。无法核实的引文、数字或方法细节标为待核实。

## `nodes[]`

- `title`：结论式标题，不能是“实验背景”“研究目标”等概括。
- `desc`：1—2 句表述结果的技术信息与定量证据。
- `page`：原文页码/结果小节/图号。
- `root`：右侧分叉树的总题。
- `branches[]`：技术/实验方法卡片，包含 `title`、`label`、`goal`、`items`，可添加 `level`（1—4）指定可视层级。
- `branch_relation`：`"parallel"`（默认，同层分叉）或 `"sequence"`（明确顺序步骤）。
- `evidence`：图表或正文证据说明。
- `figure`：关联 `figures` 字典 key，如 `"1"`；无关联可写空字符串。

### `branch_relation` 与 `branches[].level`

- `parallel` 为默认：同一 `nodes[]` 下的兄弟 `branches[]` 必须具有相同 `level`，通常均为 `1`。
- `sequence` 仅在原文明示输出进入下一步骤、且页面显示连续递进关系时使用；此时可将 `level` 设为 `1,2,3...`。
- 并列卡片必须同色；不得根据论文章节顺序、实验叙述顺序或内容深入程度自动改变颜色。
- 四级颜色采用低饱和度雾蓝灰、灰青绿、灰紫、暖灰棕。

并列示例：

```json
{
  "branch_relation": "parallel",
  "branches": [
    {"title": "数据质量控制", "level": 1, "items": []},
    {"title": "模型参数估计", "level": 1, "items": []},
    {"title": "独立验证", "level": 1, "items": []}
  ]
}
```

顺序示例：

```json
{
  "branch_relation": "sequence",
  "branches": [
    {"title": "输入准备", "level": 1, "items": []},
    {"title": "转换处理", "level": 2, "items": []},
    {"title": "独立验证", "level": 3, "items": []}
  ]
}
```

以上只说明结构；正式论文中每个 `items` 必须包括 `name`、`core`、`effect`。

## `branches[].items[]`

最低必须有 `name`、`core`、`effect`：

| 字段 | 解释 |
|---|---|
| `name` | 论文中正式的技术/实验方法名称 |
| `core` | 具体输入/前提 + 关键算法/实验机制 → 输出 |
| `effect` | 该机制解决的具体问题 |
| `role` | 并列方案、组成环节、来源证据、因果干预或独立验证等 |
| `input` | 方法输入对象、数据或培养条件 |
| `steps` | 原文明确操作顺序与关键参数 |
| `difference` | 相比基线/对照或其他方法的真实差别 |
| `limit` | 实验边界、性能不足、证据限制 |
| `source` | 图号、PDF 页码、章节 |

有详情字段时显示“查看方法细节”按钮；没有详情时不显示无效按钮。

## `figures`

```json
{
  "figures": {
    "1": {
      "image": "figures/fig1.jpg",
      "source": "Fig. 1 | PDF 第3页",
      "panels": [
        {
          "letter": "a",
          "rect": [0.08, 0.03, 0.92, 0.20],
          "title": "实验设计流程",
          "purpose": "图要解决的问题与对照关系",
          "how": "步骤、箭头、时间、分组或坐标轴/图例的详细解释",
          "result": "实验直接观察的结果；若流程图本身不提供结果，应明确说明",
          "significance": "对研究主张的证据作用",
          "limit": "无法由此图直接推断的内容",
          "source": "Fig. 1a · PDF第3页"
        }
      ]
    }
  }
}
```

所有 `rect` 坐标是相对于实际嵌入图像的比例值，不是相对于论文全页的值。`[x0,y0,x1,y1]` 表示左、上、右、下，满足 `0 <= x0 < x1 <= 1` 且 `0 <= y0 < y1 <= 1`。更换裁图后必须重新标注。

`image` 为相对路径时，相对于 `paper.json` 所在文件夹；支持 PNG、JPEG、WEBP、GIF。生成后图片与解释都嵌入 HTML。

## `terms`

`terms` 是术语名到四元素数组的映射：

```json
{
  "GRACE": [
    "Gravity Recovery and Climate Experiment",
    "重力恢复与气候实验",
    "通过精确测量地球重力场变化反演陆地水储量变化的卫星任务。",
    "本文用于获取总水储量异常。"
  ]
}
```

数组顺序必须为 `[英文全称, 中文名称, 概念解释, 在本文中的作用]`。

## 统计与证据边界

- 显著性星号须对照原文图注，不能统一假设；`n=3` 是否独立生物样本需确认。
- 不同图型的读图逻辑不同，`how` 必须按真实图型填写。
- 相关性热图的相似度不等于功能等同性。
- 敲低/过表达需说明操纵是否生效、对照、表型和统计证据。
- 原文没有报告的字段应写“原文未报告”，不得臆造。
